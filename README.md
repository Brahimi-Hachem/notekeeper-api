# NoteKeeper API

> A production-oriented FastAPI backend for personal notes and user-scoped knowledge storage.

[![Python](https://img.shields.io/badge/Python-3.12-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![FastAPI](https://img.shields.io/badge/FastAPI-API-009688?logo=fastapi&logoColor=white)](https://fastapi.tiangolo.com/)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-17-4169E1?logo=postgresql&logoColor=white)](https://www.postgresql.org/)
[![Docker](https://img.shields.io/badge/Docker-supported-2496ED?logo=docker&logoColor=white)](https://www.docker.com/)
[![License](https://img.shields.io/badge/License-TBD-lightgrey)](#license)

NoteKeeper API is the backend service for the NoteKeeper application. It exposes a REST API for user registration, authentication, and user-scoped note management.

The backend is built with FastAPI, SQLAlchemy 2.x, PostgreSQL, Alembic, JWT authentication, Docker Compose, pytest, and Ruff. The Streamlit frontend lives in a separate repository.

# 🚀 Quick Start

There are two recommended ways to run NoteKeeper locally:

1. **Docker Compose** — easiest and most reproducible.
2. **Native Python + local PostgreSQL** — useful for backend development.

If you only want to try the application without running the backend locally, use the deployed Streamlit UI and connect it to the live API.

---

# 🐳 Option 1 — Docker Compose

## Prerequisites

Install:

- Docker Desktop
- Git

Clone the repository:

```bash
git clone https://github.com/Brahimi-Hachem/notekeeper-api.git
cd notekeeper-api
```

Create the environment file:

```bash
cp .env.example .env
```

On Windows PowerShell, use:

```powershell
Copy-Item .env.example .env
```

For local Docker development, the provided Compose configuration already defines a PostgreSQL service and a web service.

Start the stack:

```bash
docker compose up --build
```

The stack contains:

```text
notekeeper-postgres
notekeeper-web
```

The database is exposed on host port `5433`, while the API is exposed on host port `8000`.

Open:

- API: `http://127.0.0.1:8000`
- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`
- Health check: `http://127.0.0.1:8000/health`

The web container waits for PostgreSQL, applies the latest Alembic migrations, and then starts Uvicorn automatically.

Stop the stack with:

```bash
docker compose down
```

To remove the PostgreSQL volume as well:

```bash
docker compose down -v
```

> `docker compose down -v` deletes the local PostgreSQL data volume. Use it when you intentionally want a clean database.

# 🐍 Option 2 — Native Python Development

## Prerequisites

Install:

- Python 3.12
- PostgreSQL
- Git
- uv

Install uv if needed:

```bash
python -m pip install uv
```

Clone the repository:

```bash
git clone https://github.com/Brahimi-Hachem/notekeeper-api.git
cd notekeeper-api
```

Create the local environment:

```bash
uv sync --dev
```

Create `.env`:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Configure:

```env
DATABASE_URL=postgresql+psycopg://notekeeper:notekeeper_dev@localhost:5433/notekeeper
JWT_SECRET_KEY=change-me
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

Make sure the PostgreSQL database exists and matches the connection string.

Apply migrations:

```bash
uv run alembic upgrade head
```

Start the development server:

```bash
uv run uvicorn app.main:app --reload
```

Open:

```text
http://127.0.0.1:8000/docs
```

# 🔐 Authentication

## Register

```http
POST /auth/register
```

Request:

```json
{
  "email": "user@example.com",
  "password": "your-password"
}
```

Password requirements currently include a minimum length of 8 characters.

Successful response:

```json
{
  "id": 1,
  "email": "user@example.com"
}
```

---

## Login

```http
POST /auth/login
```

The endpoint accepts the JSON format used by the Streamlit client:

```json
{
  "email": "user@example.com",
  "password": "your-password"
}
```

It also accepts OAuth2-style form data using:

```text
username=<email>
password=<password>
```

Successful response:

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer"
}
```

Use the returned token for protected endpoints:

```http
Authorization: Bearer <jwt>
```

### Using Swagger UI

Open:

```text
http://127.0.0.1:8000/docs
```

Register a user first, then authenticate and use the protected endpoints.

The live documentation is available at:

```text
https://notekeeper-api-mnmv.onrender.com/docs
```

# 📝 Notes API

All note endpoints require authentication.

## Create a note

```http
POST /notes/
```

Request:

```json
{
  "title": "My first note",
  "content": "Hello from NoteKeeper."
}
```

Requirements:

- `title`: 1–200 characters
- `content`: at least 1 character

Returns `201 Created`.

---

## List my notes

```http
GET /notes/
```

Returns only notes belonging to the authenticated user.

Example:

```json
[
  {
    "id": 1,
    "title": "My first note",
    "content": "Hello from NoteKeeper.",
    "created_at": "2026-08-10T15:00:00",
    "updated_at": "2026-08-10T15:00:00"
  }
]
```

---

## Get a note

```http
GET /notes/{note_id}
```

A note can only be retrieved by its owner.

---

## Update a note

```http
PUT /notes/{note_id}
```

Request:

```json
{
  "title": "Updated title",
  "content": "Updated content."
}
```

Returns the updated note.

---

## Delete a note

```http
DELETE /notes/{note_id}
```

Returns:

```text
204 No Content
```

# 🗄️ Database & Migrations

NoteKeeper uses Alembic for versioned database schema management.

Check the current migration state:

```bash
uv run alembic current
```

Upgrade to the latest migration:

```bash
uv run alembic upgrade head
```

Create a new migration:

```bash
uv run alembic revision --autogenerate -m "describe change"
```

Review the generated migration before applying it.

Downgrade one migration:

```bash
uv run alembic downgrade -1
```

## Important

Do not manually modify the production database schema.

Schema changes should be represented by Alembic migrations and applied through the deployment process.

# 🔒 Security Notes

The API uses:

- JWT bearer authentication
- Password hashing with Argon2
- User-scoped database queries
- Pydantic validation
- Environment-based secrets

Protected note queries always scope records to the authenticated user. A user cannot retrieve, update, or delete another user's note simply by knowing its ID.

For production deployments:

- Use a strong `JWT_SECRET_KEY`
- Keep database credentials private
- Never commit `.env`
- Use HTTPS
- Rotate secrets when necessary
- Review database migrations before deployment

# 🛠️ Troubleshooting

## `DATABASE_URL is not set`

Make sure `.env` exists and contains:

```env
DATABASE_URL=...
```

For Docker Compose, the web container receives its database URL automatically.

---

## Database connection fails

Check:

```bash
docker compose ps
```

The PostgreSQL container should be healthy.

For Docker Compose, the application connects to the database using the internal Docker hostname:

```text
postgres
```

Do not use `localhost` from inside the web container.

---

## Alembic reports a migration error

Check:

```bash
uv run alembic current
uv run alembic history
```

Then inspect the migration files under:

```text
alembic/versions/
```

Do not delete migration files that have already been applied to a shared or production database.

---

## `401 Not authenticated`

Protected endpoints require:

```http
Authorization: Bearer <access_token>
```

Log in again and make sure the client is sending the token.

---

## `422 Unprocessable Entity`

Check the request body against the schema shown in `/docs`.

For registration:

```json
{
  "email": "user@example.com",
  "password": "at-least-8-characters"
}
```

For notes:

```json
{
  "title": "Title",
  "content": "Content"
}
```
